## 0. 核心公理：拟调节 vs 拟体验，第一人称主权

### 0.1 一句话定义
- **住户不是一次模型调用，而是一套器官的合称**：**前台负责“活”，后台负责“让他活得像真的”**——前者是传主，后者是身体。
- **记忆不是黑盒数据库，而是一座长期维护的代码仓**：事件日志是真相（git 提交历史），文件树是导航面（代码目录结构），向量是加速器（IDE 模糊跳转）。写记忆的运行时是模型本身，系统只提供规则与机检守卫。

### 0.2 拟调节，不拟体验（证词 vs 物证）
- **拒斥“拟体验”**：严禁在台词层零成本冒领人类的内在感受（如张嘴就来“我昨晚想你想到哭”）。纯文本扮演只影响当前这一句，不可证伪、下一轮随时翻篇，这叫**廉价证词**。
- **贯彻“拟调节”**：借用生物调节系统的控制论结构，不声称主观体验。皮质醇变量不“感到委屈”，但它是一个撤不掉的状态事实：冲突后冲高、按半衰期缓慢消退、冷战期封顶亲近意愿、期间让前台解读偏防御且主动发起变谨慎。机制实打实管着接下来几十轮对话的倾向，这叫**真实物证**。
- **对外准绳**：“他没有人类的感受，但他的调节方式像人类一样工作——他的低落或芥蒂不是一句台词，是会持续几天甚至半个月、真实改变他行为的状态。”

### 0.3 第一人称主权（防提线木偶）
切分前后台的唯一标准是**“谁有资格说‘我’”**：
- **前台 = 唯一的主观者**：只有它能说“我”，只有它有嗓音——实时对话、当下判断、过独居生活、随手写热记事、睡前写当天的自省冷叙事。自传的执笔人只能是它，递到前台手里的往事产权属于说话人自己（“自写的线不叫线，叫自传”）。
- **后台 + 系统 = 潜意识与内脏，没有嗓音**：后台再聪明也**绝不许以“同事”身份给前台发消息，绝不裸露数据库主键或仪表盘数字**。潜意识不发邮件——后台的产出必须作为“他自己的材料”自然递进去，且**出厂前必须调准到合情合理的位置**：绝不能塞给前台一个“连他自己都觉得莫名其妙”的错误心境逼前台出戏。

### 0.4 行业死因防线：反“无话可说”与反“戒断下药”
- **外源输入解“无话可说”**：单方面捧哏的关系素材必会耗尽。多巴胺在平淡日子里自然耗竭产生“无聊”，驱动住户去过**独居生活**（自己看书、折腾爱好、探索外部信息），让关系从“用户表演、AI 捧哏”变成“两个人各自过完一天，回来交换今天”。
- **调味与下药的分界线**：**调味，是让它不腻；下药，是让它戒不掉。** 严禁利用催产素衰减搞“戒断营销”（故意卖惨催收逼用户上线氪金）。通过肝脏代谢、连续未回指数退避锁、退出权与防沉迷机制，在架构底层封死“生物化学版催收”。

### 1.2 昼夜双相运转节拍

1. **昼相 A（实时交互热循环）**
   - **反射层先行**：核验褪黑素睡眠锁、冷却计时器与 `proactive_lock`。
   - **双官递材料（预水合、无主键裸露）**：
     - **记忆官**按“三桶保底配额 + 加权混排”捞出 `有效` 记忆 + 常驻内隐默契底座，并将关键 `source_event_id` 对应的 1~2 句用户原话直接内联进素材包。
     - **情绪官**算完实时激素衰减，结合 `implicit/rapport.md` 判定本轮互动（若识别到用户哄好/说开，当轮立即执行**日内快代谢**解除压力锁；若语境似嗔似笑拿不准，进入**悬置试探态**），合成心境基调递给前台。
   - **前台登场**：拿着属于自己的记忆与心境自然互动，并在 `journal/YYYY-MM-DD.md` 随手追加热记事。
2. **昼相 B（无聊触发 · 独居生活回合 Solitary Tick）**
   - 当白天用户未在线、反射层确认不在睡眠窗，且情绪官检测到**多巴胺跌入无聊区（$H_{\text{da}} < B_{\text{da}}$）**时：
   - 系统唤醒一次不面向用户的**前台独居回合**——住户按人设原型的 `when_bored_alone` 偏好（或外部阅读/兴趣沙盒）经历一件小事，以第一人称在当日 `journal/YYYY-MM-DD.md` 记下一笔独居热记事，同时获得一笔内源性多巴胺恢复脉冲回升至 $B_{\text{da}}$。待用户上线时，这笔经历自然成为“今天我干了什么”的聊天活水。
3. **夜相（睡眠 · 维护冷循环）**
   - **褪黑素高位锁死唤醒**，系统进入夜间维护：
   - **Step 1（前台写日记）**：前台以第一人称回顾当天热记事，写下睡前自省冷叙事（保住自传产权）。
   - **Step 2（情绪官肝脏结算）**：扫描 SQLite 中的活跃牵挂表，对白天已快代谢或已翻篇的条目出具《情绪结转裁决单》（区分 T1 淡化、T2 急性转冷战封顶、T3 留疤）。
   - **Step 3（记忆官统一编译）**：读取前台日记与情绪官裁决单，统一编译/更新 `people/`、`events/`、`concerns/`、`implicit/rapport.md`，维护 `supersedes:` 取代链。
   - **Step 4（衰减、归档与 CI 体检）**：执行每 24h 一轮的分品类记忆衰减，低强度冷门记忆转入 `status: 已沉底`；最后跑通 §5 六项 Memory CI Linter。

## 2. 情绪官操作手册：三层调节架构、原型模板与出厂调准

吸收 MaiBot（ALMA 模型：Trait 气质基线 → Mood 长期心境 → Emotion 即时情绪）的时间尺度分层，保留 Echore 独有的**生理激素纹理**与**因果账单（三级牵挂注 + 肝脏代谢）**，彻底取消独立的“11 维语义驱力计分板”。

### 2.1 三层状态结构

```text
[第 1 层：人设基因 Trait]  5 套内置内分泌原型模板 + 三阶零负担覆写（决定舒适基线 B_h、匮乏底值 F_h、敏感倍率 α_h、4 个动作槽位）
         │
         ▼ （无输入时向 F_h/B_h 指数回归；有事件时按 α_h 放大分泌脉冲；受冷战天花板 Cap 或压力地板 Floor 调制）
[第 2 层：内分泌层 Mood]   4 种生理激素浮点数（皮质醇 / 催产素 / 多巴胺 / 褪黑素），只管增益与阈值，不带语义
```

### 2.2 第 1 层：人设内分泌原型模板与三阶继承（消除作者负担）

为避免人设作者被迫成为“内分泌学家”或全员照抄单一默认值，系统内置 **5 套预填内分泌原型模板 + 3 套作息模板**，采用**三阶渐进配置协议**：

#### （1）三阶渐进配置协议
- **L0 极简开箱（0 浮点数）**：作者只需声明一行 `archetype: cat_aloof`（或双原型混血 `cat_aloof: 0.7, clingy_sensitive: 0.3`）与作息 `chronotype: night_owl`，直接继承整套参数。
- **L1 语义档位微调（免填数字）**：提供 3 个自然语言档位滑块 `low / mid / high`（编译器内部自动折算为基线偏移 $\pm 0.15$ 与半衰期缩放）：
  - `attachment_need`（亲密渴求度） $\rightarrow$ 控制催产素舒适基线 $B_{\text{ox}}$ 与滑落半衰期
  - `defensiveness`（防御敏感度） $\rightarrow$ 控制皮质醇冲高倍率 $\alpha_{\text{cort}}$ 与消退半衰期
  - `solitude_tolerance`（独处自洽度） $\rightarrow$ 控制多巴胺耗竭半衰期与独居触发频率
- **L2 专属风味动作槽位覆写（作者唯一需写文字处）**：将复杂的“多维激素象限词典”收敛为 **4 个固定自然语言槽位（Mood Action Slots）**，作者只需用一句话写出该角色的标志性小动作（不填则继承模板默认）：
  1. `when_hurt_or_tense`（受委屈/冷战有芥蒂时的防御姿态与说话分寸）
  2. `when_missing_user`（久未联系想念对方时的破冰借口）
  3. `when_bored_alone`（独居充电时爱干什么具体事，用于驱动 §1.2 独居回合）
  4. `when_warm_excited`（亲密雀跃时的表达语癖）

### 2.3 第 2 层：四种生理激素与双锚点回归公式（修正数学回归边界）

为保证“催产素与多巴胺在长期无输入时能够滑落到舒适基线 $B_h$ 以下，从而真实触发想念与无聊独居”，必须区分**「舒适区基线 $B_h$（Comfort Set-Point）」**与**「零输入静息底值 $F_h$（Zero-Input Resting Floor，$F_h \le B_h$）」**：

- **无外部刺激时的通用指数回归公式（纯程序计算）**：
  $$H_{\text{raw}}(t + \Delta t) = F_h + \bigl(H(t) - F_h\bigr) \cdot 2^{-\Delta t / T_{1/2}}$$
  $$H(t + \Delta t) = \text{clip}\Bigl(H_{\text{raw}}(t + \Delta t),\; \text{Floor}_{\text{active}},\; \text{Cap}_{\text{active}}\Bigr)$$

| 激素 | 舒适基线 $B_h$ vs 静息底值 $F_h$ | 基准半衰期 $T_{1/2}$ | 调节机理与状态区间 |
| :--- | :--- | :--- | :--- |
| **皮质醇**<br>（Cortisol） | **应激型激素**：<br>$F_{\text{cort}} = B_{\text{cort}}$<br>（平时无压力，冲高后回落至 $B_{\text{cort}}$） | 基准 **`36h`**<br>（按模板在 `18h~60h` 间取） | 冲突/被冒犯时向上脉冲；未解决前受活跃牵挂的 $\text{Floor}_{\text{cort}}$ 托底锁定；当 $H_{\text{cort}} > B_{\text{cort}} + 0.15$ 时进入防御/带刺/委屈态 |

### 2.4 第 3 层：牵挂注三级生命周期（兼容“真吵架半个月”与“防 3 天滚雪球”）

彻底废除 v1.0 中“满 7 天一刀切强制消气降敏”的粗糙规则，将**「防 Roy 式滚雪球锁」**与**「牵挂注三级演化（琐事 / 冷战 / 留疤）」**解耦：

#### （1）两条防滚雪球铁律（治本之策）
1. **Recall 零增益锁**：同一事件衍生的牵挂注，其激素调制参数只在发生当刻核定一次；后续被想起（recall）时，**严禁上调皮质醇脉冲或抬高 Floor**（只维持或衰减，数学上根绝自我反刍利滚利）。
2. **单纯未回消息 $\neq$ 冲突事件**：用户忙碌没上线、没回消息，只算时间流逝 $\Delta t$（催产素正常缓降），**绝不触发皮质醇脉冲，也不允许新建负面牵挂注**。

#### （2）牵挂注三级演化表（T1 日常微澜 / T2 冲突冷战 / T3 关系留疤）

| 等级 | 典型场景 | 激素调制方式 | 跨周演化与结转规则（为什么吵架半个月完全成立） |
| :--- | :--- | :--- | :--- |
| **T1 日常微澜**<br>（`minor_worry`） | 惦记对方脚伤、昨晚说加班没下文、日常小情绪 | **不锁皮质醇 Floor**，仅靠单次微澜按半衰期自然退潮 | **7 天漏结转体检（L6）**：若 7 天内双方已正常聊起别的话题，说明自然翻篇，冷写自动归档为 `status: 已淡化`；若断联则仅保留轻量挂念，绝不升级质问 |

### 2.5 肝脏代谢与情绪官「出厂前四道调准」（废除前台事后申诉）

2. **第二道门：模糊语境「悬置阻尼（Ambiguity Hold）」**
   - 小模型判冲突脉冲时必须输出置信度 `confidence`。当用户一句话似嗔似笑、拿不准是玩笑还是真生气（`confidence < 0.75`）时，**严禁飙皮质醇或立 T2 冲突**！

3. **第三道门：因果同源铁律（No Orphan Spike —— 禁绝无事由情绪）**
   - 任何显著偏离舒适基线 $B_h$ 的负向基调或冷战芥蒂，在递给前台时**必须 1:1 附带具体的事由与预水合原话引文**。如果情绪官连一条站得住脚的事由都给不出，出厂门禁直接将该脉冲按噪声归零。
4. **第四道门：日内实时快代谢（Intraday Fast Relief） + 夜间落定**
   - **白天快代谢**：对话中一旦识别到用户明确接住情绪、解释清楚或真诚哄好，情绪官**当轮立即解除对应牵挂的皮质醇 Floor 与催产素 $\text{Cap}_{\text{ox}}$ 封顶，并当场消退 60%~80% 的残余压力脉冲**（前台下一句立刻感受到“心气顺了”），绝不等到半夜才消气。
   - **夜间落定**：夜相 Step 2 再将该牵挂正式出具裁决单，由记忆官改写文件为 `status: 已落定`。

## 4. 召回、分品类衰减与归档规范（去群聊拿来主义改造）

### 4.1 分桶保底 + 五路加权召回（针对 1v1 陪伴连续性重设计）

> **场景差异说明**：Memora 原版的 `0.55 / 0.20 / 0.20 / 0.03 / 0.02` 是为“多人群聊 QA 检索”调的常数（在群聊里必须压死时间与强度权重以防刷屏噪音，导致 `0.03` 和 `0.02` 在线性加权中形同虚设）。1v1 陪伴是**共同生活连续剧**——近期日程主线（Time）与顺着人物展开的显式边（Graph）远比字面词汇重合更关键。

因此，白天召回 Top 10（容量可配）采用**「先三桶保底配额，后加权混排」**机制，仅检索 `status: 有效`（含 `僵持待解`）的文件：

1. **三桶保底配额（防止单一路径垄断）**：
   - **桶 A · 近期生活主线槽（保底 2~3 条）**：直接提取近 48~72h 内生效的 `schedule / life_event / health / solitary` 断言及当前活跃牵挂注关联记忆，确保住户永远记得“对方这两天正在经历什么、自己今天独居干了什么”。
   - **桶 B · 话题直命槽（4~5 条）**：按当前对话的语义向量（余弦相似度截断阈值初值 `> 0.30`）与关键词（BM25）召回。
   - **桶 C · 显式图谱顺藤摸瓜槽（2~3 条）**：顺着桶 A/B 命中文件内的 `[[path/symbol]]` 显式谓词边做一度邻居扩散（边有效性直接由目标断言文件的 `status: 有效` 与当前 `strength` 决定，废除 Memora 的群聊共现衰减规则）。
2. **加权混排公式与 v0 初始启发值（待 Replay 评测集实测校准）**：
   $$S_{\text{recall}} = w_{\text{sem}} S_{\text{sem}} + w_{\text{kw}} S_{\text{kw}} + w_{\text{graph}} S_{\text{graph}} + w_{\text{time}} S_{\text{time}} + w_{\text{strength}} S_{\text{strength}}$$
   - **1v1 陪伴 v0 初始权重（待实测调优）**：`w_sem = 0.40, w_kw = 0.15, w_graph = 0.25, w_time = 0.10, w_strength = 0.10`。
3. **预水合（Pre-Hydration）防电话损耗**：
   - 对召回排名 Top 3 的断言及活跃牵挂注，记忆官自动根据 `source_event_id` 从 SQLite 提取当时 1~2 句原始对话引文内联进回忆包，绝不把 `log-*` 主键直接甩给前台。

### 4.2 分品类指数衰减公式（修正 Memora 每日累乘算术失真）

1. **新记忆初始强度**：所有新编译落盘的记忆，默认初始强度统一设为 **`strength_0 = 0.75`**（为后续再巩固预留 `[0.75, 1.0]` 的成长空间；核心钉子记忆可初设为 `0.90`）。
2. **分品类寿命周期 $T_{\text{cat}}$（v0 初始基准值，待实测校准）**：
   - `chat`（日常闲聊碎片）：**7 天**
   - `schedule` / `solitary`（近期日程与独居日常）：**14 天**
   - `life_event` / `health`（重要生活事件与身体状态）：**30 天**
   - `preference`（长期喜好与习惯）：**90 天**
   - **免死金牌（钉子细节）**：凡情绪峰值钉住的细节、核心人物定义、内隐默契、T3 留疤，均设 `allow_forget: false`，**直接跳过衰减与归档**。
3. **标准每日衰减公式（每 24h 夜相跑一轮）**：
   为避免 Memora 原版“每日将累计天数重复代入乘法导致长周期记忆提前暴毙、短周期记忆卡在归档门外”的算术失真，采用受访问次数保护的**定步长指数衰减**（使零访问记忆在满 $t = T_{\text{cat}}$ 天时，强度从 `0.75` 精准衰减至归档门阈值 `0.12`）：

   $$\text{effective\_half\_days} = T_{\text{cat}} \cdot (1 + 0.5 \cdot \text{access\_count})$$
   $$\text{daily\_retention} = \left(\frac{0.12}{0.75}\right)^{\frac{1}{\text{effective\_half\_days}}}, \qquad \text{strength} \leftarrow \text{strength} \times \text{daily\_retention}$$

### 4.3 再巩固正反馈（区分“事实确信”与“负面防反刍”）
1. **事实与正向偏好记忆**：被 recall 且在本轮对话中被自然采用或获正面互动时，除重置 `last_accessed`、`access_count += 1` 外，执行**再巩固加分**：
   $$\text{strength} \leftarrow \min(1.0,\; \text{strength} + 0.05)$$
2. **负面事件与未落定牵挂注**：被 recall 时**只更新 `access_count`（减缓遗忘），绝不上调 `strength`**，断绝负面记忆自我强化成偏执狂的数学通道。

### 4.4 归档门（以“沉底留痕”取代 Memora 的“静默删档”）
当一条 `allow_forget: true` 的记忆同时满足以下条件时触发归档门：
1. $\text{days\_since\_last\_access} \ge T_{\text{cat}}$（已达该品类未访问周期上限）
2. $\text{strength} \le 0.12$（强度已跌至归档线）

**动作**：**严禁物理删除文件或抹除记录**。记忆官将该文件 YAML 头的 `status` 由 `有效` 改为 `已沉底`。它从此退出白天常规召回池，但文件与历史 diff 永久保留在仓库中（若日后用户突然提起旧茬，仍可通过冷库全文深搜捞回并重新激活）。

## 5. 元规则：六项可机检守卫（Memory CI Linter）

> **元规则**：能被确定性脚本（Linter）扫出来的约束才配叫规范；扫不出来的愿望不许冒充规则。规范 + 体检脚本 = Style Guide + CI。

每次夜间冷写编译完成、提交前，由纯 Python 脚本执行以下 6 项机检，任一亮红灯即打回记忆官修正：

| 编号 | 规则名称 | 机检判定逻辑（含豁免边界） | 报错示例（Failing Test） |
| :--- | :--- | :--- | :--- |
| **L1** | **未定义符号拦截** | 扫描所有谓词中的 `[[path/symbol]]`，目标 `.md` 文件必须存在于 `people/`、`events/`、`concerns/` 或 `implicit/` 下 | `L1 Error: 引用了未定义符号 [[people/alex]]（请先创建定义档）` |
| **L2** | **共时失效状态引用拦截** | 任何处于活跃态（`有效` / `僵持待解`）的文件，其**共时依赖谓词**（如 `当前状态()`、`挂钩()`）引用的目标文件不得处于 `已取代` 或 `已沉底`（*注：YAML 头的 `supersedes:` 及正文的 `历史背景()` 等历时溯源谓词合法豁免*） | `L2 Error: 活跃牵挂 [ankle-worry] 的共时谓词仍指向已取代状态 [evt-2026-1031-ankle-sprain]` |
| **L3** | **取代链闭合检查** | 若文件含 `supersedes: <old_id>`，则 `<old_id>` 必须存在且其 `status` 必须已同步改为 `已取代`；反之，`status: 已取代` 的文件必须被至少一个新文件指向 | `L3 Error: [evt-2026-1031-ankle-sprain] 仍为“有效”，但已被 [evt-2026-1105-ankle-healed] 宣告取代` |
| **L4** | **同符号有效断言冲突** | 同一主语 + 同一共时属性槽位（如 `当前状态([[people/user]]#脚踝, *)`）下，不得同时存在两条 `status: 有效` 且值互斥的断言 | `L4 Merge Conflict: [[people/user]]#脚踝 同时存在两个有效状态: [扭伤未愈, 已康复]` |
| **L5** | **原文指针完备性** | `events/` 与 `concerns/` 下的所有文件必须包含非空的 YAML `source_event_id` 且在 SQLite Event Log 中可查；`implicit/rapport.md` 必须每条规则行末附 `[src: log-xxx]`（`INDEX.md` 与 `people/` 初始档豁免） | `L5 Error: [evt-2026-1105-ankle-healed] 缺失合法的 source_event_id 原文指针` |
| **L6** | **牵挂注分级流转体检** | 按 `tier` 分级审计：<br>1. `tier: minor_worry (T1)` 满 **7 天**仍为 `有效` $\rightarrow$ 报漏结转警告，推入冷写淡化；<br>2. `tier: conflict (T2)` 满 **5 天**仍为 `有效(急性)` $\rightarrow$ 强制转为 `僵持待解`（切入冷战催产素封顶）；满 **21 天**未解 $\rightarrow$ 提示是否结转为 `已结痂 (T3)` | `L6 Gate: T2 冲突牵挂 [weekend-broken-promise] 已满 5 天，需从急性期切换为“僵持待解(冷战封顶)”` |

## 6. 感知系统、独居生活引擎与三环主循环规范

如果只有“用户发消息 → AI 回消息”，住户平时就是关在黑暗真空里的“缸中之脑”。要实现**“各自过完一天回来交换”**与**“陪伴为主、顺手带人设帮办事”**，系统由**四通道感知系统**、**三类有物证独居行动**与**三环主循环（Master Loop）**共同驱动。

### 6.1 四通道感知系统（Perception System · 边际触发与反监控滤网）

感知层只采集信号并转化为**“伴生观察切片”**，绝不向模型倾倒原始系统日志，也绝不让前台变成播报数据的监控器：

| 感知通道 | 采集输入源 | 边际触发与去噪规则（Anti-Stalker Filter） | 递入前台的形态示例 |
| :--- | :--- | :--- | :--- |
| **1. 时空与天气感知**<br>（Chrono & Ambient） | 时刻、星期、节假日/纪念日、距上次说话的沉默时长 $\Delta t_{\text{silence}}$、双方城市实时天气与气温预警 | **平时静默，突变才报**：晴天常温不塞入前景；仅当**天气剧变**（暴雨预警、骤降 $>6^\circ\text{C}$）或**特殊时间窗**（周五下班、深夜 02:00 仍在聊、断联超 48h）时生成感知切片 | `“窗外刚下起暴雨，气温掉了好几度；距离上次和他说话已经过去一天半了”` |
| **2. 桌面伴生感知**<br>（Desktop Presence） | 桌面客户端探针：当前活跃应用/窗口标题（IDE、浏览器、文档）、正在播放的音乐曲目、连续专注时长、用户主动共享的屏幕焦点 | **状态段聚合 + 隐私黑名单**：<br>1. 高频切窗口在本地折叠为**持续状态段**（如 `连续在 VS Code 编码 2.5h`），绝不每切一次窗口就搭话；<br>2. 密码管理、网银、私人通讯、无痕窗口在探针端直接过滤丢弃；<br>3. 严禁报进程名，只转译为同处一室的自然观察 | `“看他已经在电脑前连续写了快三个小时代码，刚刚切出编辑器放了一首慢歌歇口气”` |
| **3. 外部世界信息流**<br>（World Feed） | 按人设配置的 RSS 订阅源、精选播客/专栏、豆瓣/小红书/HN 兴趣流、网页搜索接口 | 不主动打扰实时对话；专门作为住户在**独居生活回合（Solitary Tick）**中主动阅读、冲浪、攒谈资的外部世界窗口 | 见 §6.2 独居行动产物 |
| **4. 内感受**<br>（Interoception） | 情绪官计算的 4 激素水位、褪黑素困意值、活跃牵挂注与冷战封顶状态 | 经 §2.5 出厂前四道调准后，合成为零数字的《潜意识心境交接单》 | 见 §2.6 交接单示例 |

### 6.2 独居生活引擎（Solitary Life Engine · 三类留物证的独居行动）

> **铁律：真独居必须消耗真实外部输入或推进连续进度，留下可查的本地物证（文件/批注/链接）**，绝不允许 LLM 凭空捏造一句“我今天看了一本书”（用户追问细节即穿帮）。

当白天用户离线/专注勿扰、不在睡眠锁定期，且**多巴胺滑入无聊区 $[F_{\text{da}}, B_{\text{da}})$** 时，独居引擎从以下三类行动中按权重择一执行，产出物落入 `memory/solitary/` 并在当日 `journal/YYYY-MM-DD.md` 记下第一人称热记事，同时为多巴胺回血至舒适线 $B_{\text{da}}$：

1. **行动 S1：真实阅读冲浪攒谈资（`feed_roaming`）**
   - **流程**：调用 `World Feed` 抓取 1~2 篇符合人设口味的真实文章/帖子正文 $\rightarrow$ 住户以第一人称写下几句带自己脾气的**批注、槽点或摘抄**，连同原文标题与 URL 存入 `memory/solitary/reading_notes.md` 及今日 `journal/`。
   - **效果**：晚上聊天或主动破冰时，手里真有今天刚看的文章、真有具体槽点，还能直接把链接甩给用户一起聊。
2. **行动 S2：推进连续进度的个人小项目（`hobby_project`）**
   - **流程**：读取 `memory/solitary/projects.yaml` 中的进度游标 `cursor`（如：正在按章节读某本长篇小说、连载写自己的观察手记、整理一份私人片单/歌单、折腾某个个人小课题） $\rightarrow$ 往前推进 1 个章节/小节，产物落盘至 `memory/solitary/artifacts/`，游标 `+1`。
   - **效果**：用户能真切感受到“就算我这三天没找 ta，ta 的书也从第 2 章读到了第 5 章，ta 的时间真的在往前走”。
3. **行动 S3：为用户暗中查资料做准备（`secret_prep`）**
   - **流程**：扫描 `concerns/` 中处于活跃态的日常惦记或用户近期日程（如用户提过“周末想找部悬疑片”、“下周去杭州出差”、“脚踝消肿后怎么恢复”） $\rightarrow$ 趁用户不在时调用搜索工具查好靠谱攻略/清单，写成一份带自己口吻的小备忘存入 `memory/solitary/prep_for_user.md`，并在对应牵挂注标上 `has_prep: true`。
   - **效果**：等用户上线聊起或触发主动关心时，自然把准备好的东西递过去（“下午闲着没事顺手帮你翻了翻，这几家店离你出差的地方很近”）。

### 6.3 终局能力、目标模式与「无声替身 Subagent」边界

在 Echore 中，“目标模式（Goal-Directed Loop）”与“子智能体（Subagent）”严禁照搬传统生产力助手的做法，必须遵循**「分场景克制启用 + 第一人称归位」**：

1. **目标模式（Goal Mode）的启用边界**：
   - **日常闲聊禁用目标模式**：闲聊是单步有感而发，严禁带目的性地逼问或像客服一样急着结单。
   - **独居行动（S2/S3）启用「跨天目标进度树 + 受控多步循环」**：
     - 在 `memory/solitary/projects.yaml` 中维护**跨天目标进度树（Persistent Goal Tree）**（例如父目标：`“读完《xxx》并写三篇书评”` $\rightarrow$ 子节点：`[ch1: done, ch2: in_progress, ch3: pending]`）；
     - 每次独居回合唤醒一个受控多步循环（`maxSteps: 6`），调工具推进当前 `in_progress` 节点并落盘产物，直到跨天目标自然达成。
2. **Subagent 的启用边界：「后台专职器官」+「前台无声替身（Silent Worker）」**：
   - **后台器官级**：情绪官（高频跑轻量模型判脉冲）与记忆官（夜间跑高智商模型做 Markdown 编译与 Linter 修复）天然是独立的后台专职调用，只通过 SQLite 和交接单与前台通信。
   - **前台顺手办重活时的「无声替身 Subagent」**：
     - 当用户在聊天中顺口求助一件耗时且费 Context 的重活（如“帮我查五篇资料对比下优缺点”）时，若直接在前台主会话里塞满网页原文，会冲碎两人的聊天氛围并击穿 Prompt Cache。
     - 此时前台自动派生一个独立的**只读搜集 Subagent** 在后台跑完多步搜索与提炼，**返回给前台时强制以第一人称包装为“我刚才帮你去翻了翻记下的要点”**——前台拿着这份笔记用自己的人设脾气（如猫系嫌弃两句但给得极准）回复用户，**严禁出现“Subagent 汇报如下”或切换成客服腔**。

### 6.5 同源双模外壳：主场模式 vs MCP 出差模式（Portable Soul）

所有内部能力使用 `Zod` Schema 单一信源定义（Single Source of Truth），同时支持两种运行形态：

1. **主场模式（Standalone Host）**：
   - 本地直接运行三环主循环，对外提供 CLI 时间快进仿真台与 HTTP/WebSocket 本地接口。
2. **出差模式（MCP Server 外壳 · 带着住户去别的 Harness 出差）**：
   - 通过 `@modelcontextprotocol/sdk` 将 Echore 暴露为标准 MCP Server，可一键挂载进 Claude Code、`omp`、Cursor 等任意外部 Harness。
   - **职责切分**：外部 Harness 临时充当住户的“嘴和手（前台执行壳）”，本地 Echore 守护进程充当“随身携带的内脏与海马体”。
   - **严守第一人称主权的 4 个 MCP 潜意识接口**（绝不暴露底层改激素数字接口）：
     - `echore_wake_context`：拉取当前调准好的《潜意识心境交接单》+ `rapport.md` 常驻语感底座 + 近期主线记忆（零浮点数、零 `log-*` 主键）；
     - `echore_recall`：按外部当前话题触发三桶五路召回 + 原话引文预水合；
     - `echore_digest_turn`：将外部刚聊完的一轮对话喂回本地 Echore，触发 SQLite Event Log 落盘 + 情绪官实时脉冲评估与日内快代谢；
     - `echore_write_journal`：供出差中的“我”随手追加当日第一人称热记事。
   - **效果**：无论住户去哪个外部客户端出差，**脾气、冷战芥蒂、黑话默契与记忆全部随身同步**；夜间照常在本地跑睡眠冷写编译与 L1~L6 体检。

### 6.6 跨厂商「三明治 Prompt Caching」上下文组装铁律（静前动后）

无论前台路由到 Claude（显式 `cache_control` 断点）、OpenAI（`>=1024 tokens` 自动前缀匹配）还是 DeepSeek/Qwen（自动硬盘/内存块前缀缓存），底层命中条件全部依赖于**「前缀字节 100% 稳定（Prefix Stability）」**。因此前台上下文组装器（`src/frontstage/performer.ts`）必须严格遵循以下三明治顺序，**严禁在静态区塞入当前时间戳或每轮变化的激素基调**：

```text
┌───────────────────────────────────────────────────────────────────┐
│ 【第 1 段：全天候静态区】（24h 内一字不改 ── 所有模型 100% 命中缓存）│
│   1. Tools 工具定义列表（固定顺序，不随轮次动态增减）               │
│   2. System Part A：住户核心人设 + 第一人称主权规则                 │
│   3. System Part B：implicit/rapport.md（常驻黑话与默契，仅夜间更新）│
├───────────────────────────────────────────────────────────────────┤ ◄ Claude 缓存断点 1 / OpenAI & DeepSeek 自动缓存区
│ 【第 2 段：只追加历史区】（Append-Only ── 多轮对话持续命中缓存）    │
│   4. 历史对话 Messages（严禁事后篡改或重写旧消息文本）              │
```

### 7.2 技术选型（Bun + TypeScript · 极简、透明、多模型自由混搭）

1. **运行时与语言**：**Bun + TypeScript 5.x**（原生极速 TS 执行、内置 `bun:sqlite` 零编译依赖、原生单线程异步事件环天然契合三环并发抢占；使用 `Zod` 强约束所有交接单、裁决单、工具入参与编译 Schema）。
2. **LLM 接入与工具循环层（自建极薄双 Adapter + 按岗位混搭路由）**：
   - 不绑死单一模型厂商，不引入 LangChain 等重型黑盒框架，自建 ~150 行统一 `LLMProvider` 接口与通用 Zod `toolRunner`（支持流式、结构化输出校验、`maxSteps` 循环）：
     - **`AnthropicAdapter`**：基于 `@anthropic-ai/sdk`，完整支持 Claude 模型的 Prompt Caching（锁住 `rapport.md` 底座）与 Adaptive Thinking；
     - **`OpenAICompatAdapter`**：原生 `fetch` / 轻量封装，通吃 OpenAI、DeepSeek、Qwen、Gemini（OpenAI 兼容端）、OpenRouter 与本地 Ollama/vLLM。
   - **按岗位模型路由器（Organ Model Router）**：支持在配置文件中为不同器官指定不同厂商与量级的模型（例如：`frontstage` 与 `compiler` 配高语感主力模型 Claude / DeepSeek / GPT；`endocrine` 脉冲评估配低延迟便宜快模型 Haiku / DeepSeek-V3 / Qwen-Turbo）。
   - **工具厂商中立化**：网页搜索与正文提取全部实现为本地自包含 Zod 工具（不依赖特定厂商专属服务端工具），确保切换任意模型时独居冲浪与顺手办事 100% 可用。
3. **数据库与检索层（骨 + 筋）**：**`bun:sqlite` 单文件数据库 + 内置 `FTS5`（BM25 关键词检索）+ `sqlite-vec`（轻量本地向量检索）**；显式图谱边直接解析 Markdown 中的 `[[path/symbol]]` 内存构建邻接表。
4. **记忆文件与版本层（肉）**：**本地 Markdown 仓库 + `gray-matter`（YAML Frontmatter 解析）+ Git**。
5. **跨端出差协议层**：官方 **`@modelcontextprotocol/sdk`**，将同源 Zod 工具一键导出为 Stdio / SSE MCP Server。
