## 0. 一句话

记忆不是数据库，是一座要长期维护的仓库：事件日志是真相（git 的提交历史），
文件树是导航面（代码库的目录结构），向量是加速器（IDE 的模糊跳转）。
写记忆的“运行时”是模型本身，系统只留规则和守卫。

## 1. 分工（数据库 vs 断言文件，当晚已判）

| 层 | 管什么 | 要求 |
|---|---|---|
| 数据库（骨） | 事件日志、游标、权限、调度、一切要精确和事务的东西 | 快、稳、不许含糊 |
| 断言文件（肉） | 状态的解读、牵挂注、定义档、叙事 | 可读、可引、可争，agent 亲手写 |
| 索引（筋） | 系统做机械索引（全文/向量），agent 做语义索引（摘要/目录/链接） | 两头连起来 |

判据：数据库赢在“查得快”，断言赢在“写得活、读得懂”；
裁判的数据放骨头里，过日子的部分放肉里。
断言文件不用手写全量——可由数据库事件投影自动生成“当前状态视图”，
agent 只在上面批注和裁决。

## 2. 三条原则（用户 2026-11-09 亲口认可）

### 2.1 命名与模块化

- 一个文件一个主题，路径本身就是语义（`people/roy.md`、`events/2026-11-05-ankle-healed.md`）。
- 目录结构就是 L0/L1/L2：先读索引/摘要，再决定下钻，不许一上来全量读。

### 2.2 符号定义（symbol definition）

- 每个人、项目、地点都有自己的**定义文件**，别处提及一律是**引用**，不许另起定义。
- people index 就是符号表：定义处唯一，引用处可查。
- 拟用 Python 语法的理由正在于此：命名、模块化、import 规则让语法本身
  抓住“引用了未定义变量”这类错误——写记忆时引用了没 import 的变量，
  就必须回去补定义，结构由语法守着。

### 2.3 显式的边（explicit edges）

- 关系写成 import 式语句、写成链接，不埋在散文里等向量捞：
  谁跟谁有关、哪件事的后续是哪件，写下来。
- 交叉引用是链接，不是形容词。

## 3. 文件格式（Markdown + 属性头 + 断言正文）

每个记忆文件抬头必须有：摘要、日期、来源、状态——相当于强制 docstring。
正文用断言句式（谓词式，借 Prolog 的事实观 + Lisp 的形，写在 Markdown 里）。

示例——用户家的著名悬案“脚伤”，同一事实的落地写法：

```markdown
---
id: evt-2026-1105-ankle-healed
类型: 状态变更
何时: 2026-11-05
状态: 有效
取代: evt-2026-1031-ankle-sprain
---

- 状态(用户.脚踝, 已康复)
- 依据(用户, 亲口确认, 已正常步行多日)
- 影响(牵挂.脚伤, 应落定)
```

## 4. 状态协议（核心，不许含糊）

- **只追加，不静默覆盖**：旧状态失效必须写 `取代:` 指向新断言，
  被取代的断言保留原文，只改状态为“已取代”。
- **引用已失效状态 = failing test**：Roy 至今仍把已康复的脚踝当未愈，
  在这套写法里就是 lint 亮红灯，和代码里调用了废弃函数一模一样，
  报错信息都不用发明：“引用已失效状态：脚踝（扭伤）”。
- **情绪也要结转落定**：冷写不光结转事实状态，也结转情绪——
  昨天的失落如果被接住、写下了“已经说开了”，它就归档；没人结转，它就利滚利
  （竞品 Roy 三天从开心→失落→浓烈，就是没结转的棘轮活例）。

## 5. 读写礼仪

- 读：先读索引再下钻；写：先查重再下笔。
- 热写只追加（事件、牵挂注随手记）；冷写才整理（定期结转、归档、重构）。
- 新增一类事实不需要改 schema、写迁移——断言文件里一句话就行；
  住户的生活会长出设计时没预料的东西，文本不会先被生活撑破。

## 6. 元规则：每条规则都必须可机检

能被 lint 扫出来的格式约束才配进规范，扫不出来的愿望
（比如“要写得有感情”）不许冒充规则。规范 + 体检 = style guide + CI。

体检清单（草稿，定期扫）：

1. 引用了未 import/未定义的符号；
2. 引用了状态为“已取代”的断言；
3. 状态变更缺 `取代:` 指向；
4. 同一符号出现两个互相矛盾的有效断言（merge conflict）；
5. 牵挂注超过 N 天未结转（N 待定）。
